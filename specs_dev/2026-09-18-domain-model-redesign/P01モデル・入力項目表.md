# P01 モデル・入力項目表

更新日: 2026-09-18
状態: P01の仕様整理完了。回答の経緯は方針確認記録.mdに保存。実装未着手。

## 目的と完成条件

商品・所有ボトル・観察・メモを分離し、名前だけの登録、同一商品の複数本、同一秒の複数観察を扱う。各入力の所属・任意性・意味・制約と検索候補の表示を確定してP02へ渡す。

## モデル・入力項目

以下の必須／任意はユーザー入力についての区別。ID、関連ID、認証ユーザー、作成更新日時はシステム側の管理情報として別に扱う。API・DBの具体的な空値表現はP02で決める。

| 所属 | 項目 | 入力・扱い |
| --- | --- | --- |
| Honey | 日本語名 | 必須。名前だけで商品と最初のボトルを登録できる |
| Honey | 英語名 | 任意。日本語名とは別フィールド、name_en相当 |
| Honey | 養蜂家 | 任意の関連情報 |
| Honey | 蜜源植物 | 任意・複数。登録種類数1〜2で単花蜜、0または3以上で百花蜜 |
| Honey | 蜂蜜の種類 | 蜜源の登録種類数に従う。独立した必須入力にしない |
| Honey | 産地 | 複数国・複数地域。国コードと自由記述地域。産地不明は空、国のみでもよい |
| HoneyBottle | 商品・所有者 | Honeyへの所属と所有ユーザーを管理。同じ商品でも物理的な1本ごとに独立ID |
| HoneyBottle | 採蜜年 | 任意。2000〜2500年（両端を含む） |
| HoneyBottle | 購入日・開封日・消費完了日 | 任意の有効な日付。未来日・前後関係を理由に拒否しない |
| HoneyBottle | 初期量・残量 | 任意、0以上の整数g。残量≦初期量を検証。初期量が空なら最初に入力した残量を初期量にも設定。後から修正可能 |
| HoneyBottle | ロット番号 | 任意 |
| HoneyBottle | 用途・タグ | 任意、ボトル所属。具体的な入力UIはP02で整理 |
| HoneyObservation | 観察日時 | JST・秒精度。未指定時は登録時の現在日時。作成更新日時とは別 |
| HoneyObservation | 色 | 任意の自由記述。「薄い黄色」「琥珀色」など。固定候補ではない |
| HoneyObservation / Aroma | 香りの強さ・種類・補足 | 強さは任意評価。種類は花・果実・ハーブ・木・スパイス・カラメル・発酵の複数選択＋その他自由記述 |
| HoneyObservation / Taste | 甘さ・酸味・苦味／えぐみ・口当たり・余韻・補足 | 任意。苦味とえぐみは1評価項目。数値評価と自由記述の補足 |

| HoneyObservation | 水分量 | 任意。0〜100％、小数第1位まで。整数入力も許可し、表示は例として20.0％。未入力は0.0％に変換しない |

| HoneyObservation | deleted_at | 通常は未設定。削除時に設定し、通常の一覧・詳細から除外 |

所属ユーザーのみが読み書きする。Honeyの所属表現とBottle.ownerの整合を担保する具体的なフィールド・保存方式はP02で決める。

## 評価の数値と両端

全項目0〜10の整数。中央は5。初期値はnullで、0も5も自動保存しない。ユーザーから両端の意味の整理を任された範囲として、以下に定義する。

| 項目 | 0 | 10 |
| --- | --- | --- |
| 香りの強さ | 香りを感じない | 非常に強い |
| 甘さ | 甘さを感じない | 非常に強い |
| 酸味 | 酸味を感じない | 非常に強い |
| 苦味・えぐみ | 苦味・えぐみを感じない | 非常に強い |
| 口当たり | サラサラ | とろみが強い |
| 余韻 | ほとんど残らない | 非常に長く残る |
| 結晶化レベル | 結晶化していない | 全体が結晶化している |
| 結晶の質感 | クリーミー | ザラザラ |
| 好み | 好みに合わない | とても好みに合う |

### 意味上の注意

- 強さ・長さ・結晶化の程度の5は「中程度」であり、相反する評価の中立という意味ではない。中央の数値は5で統一する。
- 口当たりの尺度はとろみの程度を表す。「滑らかさ」はとろみと両立するため、同じ数直線の中間ラベルにはせず、メモで補足する。
- 結晶化していない場合の結晶の質感は未評価nullで表現できる。未評価をクリーミーの0へ変換しない。
- 数値の両端は物理測定の絶対値ではなく、ユーザーの観察・主観評価である。

## 検索・表示・操作

- 蜂蜜名・養蜂場名・購入年などでサーバー検索する。購入年はBottleの購入日を参照する。
- 候補はボトル単位。同一Honeyに3本あれば3行表示する。件数で区切らず全件表示し、100件を上限にはしない。
- 名前・産地・養蜂家・購入日／年・BottleId・残量を表示し、個体ごとの差を識別できるようにする。任意情報が未入力であっても表示対象から除外しない。
- 追加先を選ぶ場合は、候補のBottleが所属するHoneyへ新しい1本を登録する。既存Bottleの残量等を変更する操作ではない。
- 候補がなければ新規商品と最初の1本を登録する。
- 観察は同一Bottle・同一秒でも別IDで登録できる。不要な観察は指定IDで論理削除する。

## 量の初期設定と編集

- 初期量・残量とも空の登録を許可する。量の入力を新たな必須条件にしない。
- 初期量が未設定の状態で初めて残量を入力した場合、その値を初期量にも設定する。既に初期量があれば、残量の更新に合わせて上書きしない。
- 初期量は後から修正できるが、修正後も残量≦初期量を満たす必要がある。不整合はエラーとし、残量を黙って補正しない。
- 量は概算の整数gで扱い、小数値は受け付けない。業務上の独自の最大量は追加しない。整数の表現可能範囲と超過入力の検証はP02の型・API・DB契約で統一する。

## 日時と並び順

- 観察日時は明示入力を優先し、未指定なら登録時の現在日時をJST・秒精度で設定する。
- 有効な日付・日時かを検証するが、未来日時や購入・開封等の前後関係によって拒否しない。
- 時系列の並び順は対象の日付・日時を基準とする。IDの大小を購入順・観察順・登録順の代用にしない。
- 実装時はソート処理の近くに「ID順と日付順は一致するとは限らないため、日付・日時で並べる」旨の日本語コメントを残す。
- 画面ごとの昇順／降順、日付未入力の配置、同一日時の安定した並び順はP02の画面・取得契約で定める。同一秒の観察は省略・統合しない。
